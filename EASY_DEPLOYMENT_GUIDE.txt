1. ARCHITECTURAL OVERVIEW & PREREQUISITES
====================================================================================================
AgroVision AI consists of 4 distinct services that work harmoniously:
1. MongoDB Database: Stores users, detection records, and crop statistics (port 27017).
2. Python FastAPI Service: Runs YOLOv8 inference on uploaded leaf images (port 8000).
3. Node.js Express Server: Handles auth, database operations, rate limiting, and uploads (port 5000).
4. React Frontend (Vite + Nginx): The user-facing web interface (port 80 in Docker, port 5173 locally).

PREREQUISITES BY METHOD:
- Method 1 (Docker): Only requires Docker Desktop (Windows/Mac) or Docker Engine (Linux).
- Method 2 (Cloud PaaS): Free GitHub, MongoDB Atlas, Render, and Vercel accounts.
- Method 3 (Linux VPS): An Ubuntu 22.04 LTS server with root access.

2. PRE-CONFIGURED DOCKER ARCHITECTURE (RECOMMENDED METHOD - 1 COMMAND BOOT)
====================================================================================================
All Dockerfiles, Nginx proxy configs, and `docker-compose.yml` are already created and configured 
in your project. You do not need to install Node, Python, or MongoDB manually on the host system.

----------------------------------------------------------------------------------------------------
A. SERVICE CONTAINER MATRIX:
----------------------------------------------------------------------------------------------------
CONTAINER NAME         IMAGE / BUILD PATH       PORT MAPPING    PURPOSE
----------------------------------------------------------------------------------------------------
1. agrovision-client   ./client (Multi-stage)   80:80           React 19 SPA served via Nginx Alpine
2. agrovision-server   ./server (Node 20)       5000:5000       Express REST API & Multer Uploads
3. agrovision-ml       ./ml_service (Py 3.10)   8000:8000       FastAPI + YOLOv8 inference service
4. agrovision-mongodb  mongo:6.0                27017:27017     NoSQL Database

PERSISTENT VOLUMES (Data Safe Across Restarts):
- `agrovision_mongo_data`: Mounts to `/data/db` in MongoDB to retain all user accounts and scans.
- `agrovision_upload_data`: Mounts to `/app/uploads` in Express so leaf photos are never lost.

ISOLATED NETWORK:
- `agrovision-network`: High-speed Docker bridge network enabling service-to-service DNS resolution 
  (e.g., Express connects directly to `mongodb://mongodb:27017/agrovision` and `http://ml_service:8000/predict`).

----------------------------------------------------------------------------------------------------
B. COMPONENT DOCKER CONFIGURATION BREAKDOWN:
----------------------------------------------------------------------------------------------------
1. Client Multi-Stage Build (`client/Dockerfile`):
   - Stage 1 (`build`): Uses `node:20-alpine` to install dependencies and execute `npm run build` 
     with `VITE_API_URL=/api`.
   - Stage 2 (`production`): Uses ultra-light `nginx:alpine` (~25MB). Copies compiled assets into 
     `/usr/share/nginx/html` and deploys our custom `client/nginx.conf`.
   - Result: Blazing fast response times and tiny container size.

2. Client Nginx Reverse Proxy (`client/nginx.conf`):
   - Route `/`: Serves the React SPA with `try_files $uri $uri/ /index.html;` for client routing.
   - Route `/api/`: Proxies calls internally to `http://server:5000/api/`.
   - Route `/uploads/`: Proxies uploaded image requests to `http://server:5000/uploads/`.
   - Why this is superior: Browsers communicate with port 80 only. CORS errors are 100% eliminated 
     and HttpOnly session cookies are strictly same-site, ensuring login never fails.

3. Express Backend Container (`server/Dockerfile`):
   - Uses `node:20-alpine`.
   - Installs production dependencies via `npm install --omit=dev`.
   - Pre-creates `/app/uploads` with proper permissions.
   - Starts with `npm start` (port 5000).

4. Python FastAPI ML Container (`ml_service/Dockerfile`):
   - Uses `python:3.10-slim`.
   - Installs Linux graphics libraries (`libgl1`, `libglib2.0-0`) required by OpenCV and PIL.
   - Pre-installs CPU-optimized PyTorch (`--index-url https://download.pytorch.org/whl/cpu`).
   - Advantage: Reduces container download size from 4.2GB down to ~700MB and prevents out-of-memory errors.
   - Starts Uvicorn on `0.0.0.0:8000`.

3. Private Mesh DNS: Services communicate directly via *.railway.internal with zero egress latency.

QUICK DEPLOYMENT SEQUENCE ON RAILWAY:

5. Add Backend: Click "+ Create" -> "GitHub Repo" -> Root Directory `/server`.

   - Generate Public Domain for server.
6. Add Client: Click "+ Create" -> "GitHub Repo" -> Root Directory `/client`.
   - Variable: `BACKEND_URL=http://server.railway.internal:5000`.

====================================================================================================
Use this method if you want a public URL (e.g. `https://agrovision.vercel.app`) without hosting 
Docker on your own machine.

----------------------------------------------------------------------------------------------------
STEP 1: SETUP CLOUD DATABASE (MONGODB ATLAS)
----------------------------------------------------------------------------------------------------
1. Go to https://www.mongodb.com/cloud/atlas and create a free account.
2. Create a Free Shared M0 Cluster.
3. Add a Database User:
   - Username: `agro_user`
   - Password: `YourPassword123`
4. Under Network Access:
   - Add IP `0.0.0.0/0` (Allow Access from Anywhere).
5. Copy your connection string:
   `mongodb+srv://agro_user:YourPassword123@cluster0.abcde.mongodb.net/agrovision?retryWrites=true&w=majority`

----------------------------------------------------------------------------------------------------
STEP 2: DEPLOY ML SERVICE (PYTHON FASTAPI ON RENDER)
----------------------------------------------------------------------------------------------------
1. Push code to GitHub.
2. In Render (https://render.com), click "New +" -> "Web Service".
3. Connect your repository.
4. Settings:
   - Name: `agrovision-ml`
   - Root Directory: `ml_service`
   - Runtime: `Python 3`
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - Instance Type: Free
5. Deploy and copy your live URL: e.g. `https://agrovision-ml.onrender.com`.

----------------------------------------------------------------------------------------------------
STEP 3: DEPLOY EXPRESS BACKEND (NODE.JS ON RENDER)
----------------------------------------------------------------------------------------------------
1. In Render, click "New +" -> "Web Service".
2. Settings:
   - Name: `agrovision-backend`
   - Root Directory: `server`
   - Runtime: `Node`
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: Free
3. Environment Variables:
   - `NODE_ENV`: `production`
   - `PORT`: `5000`
   - `MONGO_URI`: `mongodb+srv://agro_user:YourPassword123@cluster0.abcde.mongodb.net/agrovision?retryWrites=true&w=majority`
   - `JWT_SECRET`: `your_production_secret_key_9988`
   - `ML_SERVICE_URL`: `https://agrovision-ml.onrender.com/predict`
   - `CLIENT_URL`: `https://agrovision.vercel.app`
4. Deploy and copy your live URL: e.g. `https://agrovision-backend.onrender.com`.

----------------------------------------------------------------------------------------------------
STEP 4: DEPLOY REACT FRONTEND (VERCEL)
----------------------------------------------------------------------------------------------------
1. In Vercel (https://vercel.com), click "Add New..." -> "Project".
2. Import repository.

   - Framework Preset: `Vite`

   - Build Command: `npm run build`

6. PRE-DEPLOYMENT CODE ADJUSTMENTS & CROSS-DOMAIN COOKIES
====================================================================================================
When deploying frontend and backend across different domains (e.g. Vercel + Render, or Railway):

1. CORS Whitelist (`server/index.js`):
   Our updated `server/index.js` dynamically reflects incoming origins with `credentials: true`. 
   If restricting in production, pass `process.env.CLIENT_URL`.

2. Cross-Domain Cookie Requirements (`server/routes/auth.js`):
   Browsers block cross-domain cookies unless:
   - `secure: true` (Requires HTTPS)
   - `sameSite: 'none'` (Allows cross-domain transmission)
   *Note: In our updated code, set `CROSS_DOMAIN=true` in production environment to activate this automatically!*

7. CRITICAL DEPLOYMENT PITFALLS & HOW TO AVOID THEM
====================================================================================================

PITFALL 1: Render Free Tier Cold Starts
- Free services sleep after 15 minutes of inactivity. First request takes ~45 seconds to wake up.
- Remedy: Open both the ML and Backend URLs in your browser 5 minutes before your presentation demo!

PITFALL 2: Docker Port Conflicts on Port 80
- Problem: If local IIS, Apache, or Skype uses port 80 on Windows, Docker will throw `bind: address already in use`.
- Remedy: In `docker-compose.yml`, change client port mapping from `"80:80"` to `"3000:80"`, then access `http://localhost:3000`.

PITFALL 3: Uploaded Photos Lost on Container Deletion
- Problem: Running `docker compose down -v` deletes named volumes.
- Remedy: Use `docker compose down` (WITHOUT `-v`) to preserve database entries and uploaded leaf photos. On Railway, always attach a Persistent Volume to `/app/uploads`.
