1. OVERVIEW OF CONFIGURED DOCKER SERVICES:
----------------------------------------------------------------------------------------------------
Your project is now fully configured with an enterprise-grade multi-container architecture:

SERVICE NAME          CONTAINER NAME         PORT MAPPING        DESCRIPTION
----------------------------------------------------------------------------------------------------
1. client             agrovision-client      80:80               React 19 Vite SPA (Nginx Alpine)
2. server             agrovision-server      5000:5000           Node.js Express REST Backend
3. ml_service         agrovision-ml          8000:8000           Python FastAPI + PyTorch YOLOv8
4. mongodb            agrovision-mongodb     27017:27017         MongoDB 6.0 Database

PERSISTENT VOLUMES CREATED:
- agrovision_mongo_data  -> Persists all user accounts, scan histories, and disease records.
- agrovision_upload_data -> Persists all uploaded crop leaf images across restarts.

INTERNAL NETWORK:
- agrovision-network (Isolated bridge network connecting all 4 containers seamlessly).

2. PREREQUISITES:
====================================================================================================
- On Windows: Install and start Docker Desktop (ensure WSL2 backend is running).
- On Linux (Ubuntu): Ensure docker and docker-compose are installed:
  `sudo apt update && sudo apt install -y docker.io docker-compose-v2`
- On macOS: Install and start Docker Desktop.


====================================================================================================
3. HOW TO LAUNCH THE FULL SYSTEM (ONE COMMAND):
====================================================================================================
Open your terminal (PowerShell, Command Prompt, or Bash) in the project root:
  cd c:\Users\Abrooo\Desktop\AgroVision\agrovision-ai

Run the build and launch command:
  docker compose up -d --build

WHAT THIS COMMAND DOES:
1. Builds the React 19 client into optimized production static assets and loads Nginx Alpine.
2. Builds the lightweight Node.js Express backend container.
3. Builds the Python 3.10 FastAPI ML container with CPU-optimized PyTorch and Pillow.
4. Pulls official MongoDB 6.0 image.
5. Initializes the persistent disk volumes.
6. Connects all 4 containers onto the `agrovision-network` and launches them in detached mode (-d).

====================================================================================================
5. ESSENTIAL DOCKER MANAGEMENT COMMANDS:
====================================================================================================
Check running container status:
  docker compose ps

View real-time live logs from all containers:
  docker compose logs -f

View logs from a specific container:
  docker compose logs -f client
  docker compose logs -f server
  docker compose logs -f ml_service
  docker compose logs -f mongodb

Restart a specific container (e.g. after updating code):
  docker compose restart server

Stop all containers (without losing database or uploaded images):
  docker compose down

Stop and completely remove all containers, networks, and persistent data:
  docker compose down -v


====================================================================================================
6. WHY THIS DOCKER ARCHITECTURE IS ROBUST:
====================================================================================================
1. Zero CORS Issues:
   Nginx listens on port 80 and reverse-proxies both `/api/` and `/uploads/` to the backend. The browser 
   makes same-origin requests, eliminating cross-domain blocking entirely.

2. Reliable Session Cookies:
   Because the frontend and API share port 80 via Nginx, HttpOnly JWT cookies are treated as strictly 
   same-site, ensuring 100% login persistence across all browsers without third-party cookie restrictions.

3. Persistent Storage:
   Uploaded leaf photos are stored inside the named Docker volume `agrovision_upload_data`, meaning 
   photos are never lost if a container crashes, updates, or restarts.

4. Lightweight ML Footprint:
   The ML Dockerfile pre-installs the official CPU wheel for PyTorch, reducing image size from ~4GB 
   down to ~700MB for fast build times and low memory consumption.
